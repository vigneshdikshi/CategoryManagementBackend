# Category Management Backend

ASP.NET Core Web API + PostgreSQL + Entity Framework Core + Swagger/OpenAPI.

This backend supports three-level categories and products that must belong to Level 3 categories. Category codes are generated by the backend as five-character strings (`00001`, `00002`, etc.) using the database identity value. Internal numeric IDs are used for database relationships; the category code is the public display code.

> This starter is for local development. It does not include production authentication/authorization or an image-upload service. Add those before exposing admin write endpoints publicly.

## Requirements

- .NET 10 SDK
- PostgreSQL 16+ (PostgreSQL 18 should also work)
- PowerShell or terminal
- Internet access for the first NuGet restore

Check .NET:

```powershell
dotnet --version
```

The installed SDK should report `10.0.x`. If your environment only has .NET 8 or .NET 9, install .NET 10 SDK or change `TargetFramework` and package versions together to a supported version.

## 1. Create the PostgreSQL database

Open pgAdmin Query Tool or `psql` as a database administrator and run:

```sql
CREATE DATABASE category_management;
```

Then configure the connection string in `src/CategoryManagement.Api/appsettings.json`:

```json
"ConnectionStrings": {
  "DefaultConnection": "Host=localhost;Port=5432;Database=category_management;Username=postgres;Password=YOUR_POSTGRES_PASSWORD"
}
```

Replace `YOUR_POSTGRES_PASSWORD` with your actual local PostgreSQL password. Do not commit real production credentials to source control.

Alternatively, set the connection string as an environment variable in PowerShell (applies to this terminal session):

```powershell
$env:ConnectionStrings__DefaultConnection="Host=localhost;Port=5432;Database=category_management;Username=postgres;Password=YOUR_POSTGRES_PASSWORD"
```

## 2. Open the project

Extract the ZIP, then open PowerShell in the extracted `CategoryManagementBackend` folder:

```powershell
cd CategoryManagementBackend
```

Restore packages and build:

```powershell
dotnet restore
dotnet build
```

## 3. Install the EF Core command-line tool

Install the tool if it is not already installed:

```powershell
dotnet tool install --global dotnet-ef --version 10.0.0
```

If already installed, update it:

```powershell
dotnet tool update --global dotnet-ef --version 10.0.0
```

If PowerShell cannot find `dotnet-ef`, close and reopen the terminal, then run `dotnet ef --version`.

## 4. Create the database schema

Run these commands from the solution root:

```powershell
dotnet ef migrations add InitialCreate --project src/CategoryManagement.Api --startup-project src/CategoryManagement.Api
dotnet ef database update --project src/CategoryManagement.Api --startup-project src/CategoryManagement.Api
```

The migration creates `categories` and `products` tables. You only need to add the initial migration once. For later model changes, create a new migration with a new name and run `database update`.

## 5. Run the API

```powershell
dotnet run --project src/CategoryManagement.Api
```

The configured launch profile listens on:

- HTTP: `http://localhost:5080`
- HTTPS: `https://localhost:7080`
- Swagger UI (development): `http://localhost:5080/swagger`
- Health check: `http://localhost:5080/api/health`

Use HTTP locally if your local HTTPS certificate is not configured. If using HTTPS, trust the developer certificate with:

```powershell
dotnet dev-certs https --trust
```

## 6. Test in Swagger UI

Open `http://localhost:5080/swagger`. Expand an endpoint, click **Try it out**, enter the request body/query, then click **Execute**.

### Suggested test sequence

#### A. Health check

`GET /api/health`

Expected: HTTP 200 and `{"status":"ok","database":"connected"}`.

#### B. Create Level 1 category

`POST /api/categories`

```json
{
  "name": "Footwear",
  "isActive": true
}
```

Expected: HTTP 201. The response contains a generated code like `"00001"` and `"level": 1`. Note the numeric `id`.

#### C. Create Level 2 category

`POST /api/categories`

Use the parent numeric `id` returned by step B:

```json
{
  "name": "Men",
  "parentId": 1,
  "isActive": true
}
```

Expected: level 2. Use the actual ID from your response rather than assuming it is 1.

#### D. Create Level 3 category

`POST /api/categories`

```json
{
  "name": "Sneakers",
  "parentId": 2,
  "isActive": true
}
```

Use the actual ID returned for Men. Expected: level 3.

#### E. List categories

- `GET /api/categories?level=1` — root categories
- `GET /api/categories?parentId=1` — direct children of category ID 1
- `GET /api/categories?level=3` — all Level 3 categories
- `GET /api/categories/code/00003` — lookup by category code

Codes depend on the order of records created in the database; use the code returned by the API, not an assumed value.

#### F. Create a product

`POST /api/products`

Use the numeric ID of the Level 3 category:

```json
{
  "name": "Running Sneakers",
  "description": "Lightweight everyday running sneakers",
  "price": 2499.00,
  "imageUrl": "https://example.com/running-sneakers.jpg",
  "stockQuantity": 25,
  "categoryId": 3
}
```

Expected: HTTP 201. The response includes `categoryCode` and `categoryName`.

The image URL is a sample external URL; this API stores the URL only and does not upload image files.

#### G. List products

- `GET /api/products`
- `GET /api/products?categoryCode=00003`
- `GET /api/products?page=1&pageSize=20`

Use the actual Level 3 category code from the API response.

#### H. Update and delete

- `PUT /api/categories/{id}` — update category name or active status.
- `PUT /api/products/{id}` — update product fields.
- `DELETE /api/products/{id}` — soft-deletes a product (sets `isActive` to false).
- `DELETE /api/categories/{id}` — deletes a category only if it has no children or products.

## 7. Endpoint summary

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Check database connection |
| GET | `/api/categories` | List categories |
| GET | `/api/categories/{id}` | Get category by internal ID |
| GET | `/api/categories/code/{code}` | Get category by public code |
| POST | `/api/categories` | Create category |
| PUT | `/api/categories/{id}` | Update category |
| DELETE | `/api/categories/{id}` | Delete empty category |
| GET | `/api/products` | List products, optional category filter |
| GET | `/api/products/{id}` | Get product |
| POST | `/api/products` | Create product |
| PUT | `/api/products/{id}` | Update product |
| DELETE | `/api/products/{id}` | Soft-delete product |

## 8. React Native connection

Configure the base URL in the frontend API client:

- Android Emulator: `http://10.0.2.2:5080/api`
- iOS Simulator (macOS): `http://localhost:5080/api`
- Physical phone: `http://YOUR_COMPUTER_LAN_IP:5080/api` (phone and computer must be on the same network; allow the port through your firewall)

Example Axios setup:

```typescript
import axios from "axios";

export const api = axios.create({
  baseURL: "http://10.0.2.2:5080/api",
  timeout: 15000,
  headers: { "Content-Type": "application/json" }
});
```

For Android local development, cleartext HTTP may require a development-only Android network security setting. Do not disable transport security in production. Use HTTPS for deployed apps.

## 9. Important design notes and limitations

- Category code is generated from the database identity and formatted to five digits. It is returned as a string so leading zeroes are preserved.
- Category codes are unique and are not reused after a category is deleted.
- A category's `id` is the internal foreign key. `categoryCode` is the human-readable code shown in the app.
- This implementation allows a category to be created only up to level 3.
- Products can only be created in active Level 3 categories.
- The API currently uses permissive development CORS and has no authentication. Restrict CORS and add JWT authentication plus admin authorization before production deployment.
- `imageUrl` stores a URL; actual multipart image upload and cloud storage are not included.
- The first migration is generated locally by the EF Core commands above; the ZIP intentionally does not include generated migration files.
